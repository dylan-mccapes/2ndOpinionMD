## Overview
The repository contains multiple generations of ETL loaders for medical ontologies, representing an evolution from legacy implementations to modern unified systems supporting both ICD-10-CM and ICD-11 with vector embeddings.

## Loader Architecture Evolution

### Generation 1: Legacy Loaders (server/scripts/)

#### load_icd10_data.py
**Purpose**: Original PostgreSQL loader for ICD-10 main codes and addenda
**Database Target**: medical_knowledge table
**Format Support**: Fixed-width text format
**Key Features**:
- Processes ICD-10 main codes from text files
- Handles addenda (Add/Delete operations)
- Uses mock embeddings for testing (numpy.random.random(1536))
- Batch processing with 500-entry batches
- Async database operations with SQLAlchemy
- Supports multiple file locations (project dir, env vars, ~/Documents)

**File Processing Logic**:
```python
# Main codes: regex pattern '^([A-Z0-9]+)\s+(.+)$'
# Addenda: 'Add:' and 'Delete:' prefixed lines
# Content format: "ICD-10 Code: {code}\nCondition: {description}"
```

**Database Schema**: 
- content_type: 'icd10_condition'
- title: condition description
- content: formatted code + description
- icd10_code: extracted code
- meta_data: source tracking and line numbers
- embedding: Vector(1536) for similarity search

### Generation 2: Modern Loaders (root directory)

#### load_icd10cm.py
**Purpose**: Hierarchical ICD-10-CM loader for ontology.icd table
**Database Target**: ontology.icd table (basic schema)
**Format Support**: Official ICD-10-CM hierarchy files
**Key Features**:
- Parses hierarchical structure with parent-child relationships
- Builds full path breadcrumbs for navigation
- Handles foreign key constraints properly
- Creates proper code hierarchy (3-char to 7-char codes)
- Batch processing with parent relationship resolution

**Hierarchy Processing**:
```python
# Determines hierarchy level by code length and structure
# 3-char codes (A00-Z99): top level categories
# 4-char codes (A000-Z999): subcategories  
# 5-7 char codes: detailed classifications
# Full path construction: "A00 > A000 > A000.1"
```

## Database Schema Comparison

### Legacy Schema (medical_knowledge table)
```sql
CREATE TABLE medical_knowledge (
    id UUID PRIMARY KEY,
    content_type VARCHAR NOT NULL,
    title VARCHAR NOT NULL,
    content TEXT NOT NULL,
    icd10_code VARCHAR,
    meta_data JSON,
    embedding vector(1536),
    created_at TIMESTAMP DEFAULT NOW()
);
```

### Unified Schema (ontology.icd table)
```sql
CREATE TABLE ontology.icd (
    id SERIAL PRIMARY KEY,
    system VARCHAR(20) NOT NULL,
    version VARCHAR(10),
    code VARCHAR(20) NOT NULL,
    short_description TEXT,
    long_description TEXT,
    parent_code VARCHAR(20),
    full_path TEXT,
    class_kind VARCHAR(50),
    foundation_uri TEXT,
    linearization_uri TEXT,
    term_vector vector(1536),
    term_vector_json JSON,
    metadata JSONB,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```
