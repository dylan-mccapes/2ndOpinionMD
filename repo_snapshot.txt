## Executive Summary

The 2ndOpinionMD-MVP repository is a comprehensive medical knowledge graph platform focused on autoimmune disease diagnosis. It implements a dual database architecture (MongoDB + PostgreSQL with pgvector), multiple FastAPI applications, and sophisticated ETL loaders for medical ontologies (ICD-10-CM, ICD-11). The codebase is currently in a transitional state with legacy, modern, and unified loader implementations coexisting.

## Repository Architecture Overview

### 1. Three FastAPI Application Versions

#### Version 1: MongoDB + ChromaDB (server/api/app.py)
- **Database**: MongoDB for user data, ChromaDB for vector search
- **Vector Engine**: ChromaDB with OpenAI embeddings (text-embedding-3-small)
- **Authentication**: MongoDB-based user management
- **Collections**: disease, citation, case, condition, autoimmune, patient
- **Key Features**: 
  - Security middleware blocking sensitive paths
  - Rate limiting (5 req/min auth, 60 req/min general)
  - Encrypted logging system
  - RAG-based diagnosis generation

#### Version 2: PostgreSQL + pgvector (server/api/app_postgres.py)
- **Database**: PostgreSQL with pgvector extension for both user data and vector search
- **Vector Engine**: PostgreSQL pgvector with cosine similarity
- **Authentication**: PostgreSQL-based user management
- **Content Types**: icd10_condition, disease, case, icd10_drug
- **Key Features**:
  - Same security middleware as Version 1
  - Database initialization on startup
  - ICD-10 code integration in responses
  - Async database operations

#### Version 3: Shared Journal Component (server/api/journal.py)
- **Purpose**: Shared journaling functionality used by both app versions
- **Features**:
  - AI-powered journal analysis using "ethos of health model"
  - STAX levels (Z-Axis progression) for disease complexity
  - Zone-based patient stability assessment (Zones 1-5)
  - Dual database support (MongoDB fallback to PostgreSQL)
  - Symptom extraction and categorization
  - Environmental factor tracking

### 2. ETL Loader Architecture

#### Legacy Loaders (server/scripts/)
- **load_icd10_data.py**: Original PostgreSQL loader for ICD-10 main codes and addenda
  - Processes fixed-width text format
  - Loads into medical_knowledge table
  - Uses mock embeddings for testing
  - Supports both main codes and addenda files

#### Modern Loaders (root directory)
- **load_icd10cm.py**: Hierarchical ICD-10-CM loader for ontology.icd table
  - Parses official ICD-10-CM hierarchy file
  - Builds parent-child relationships
  - Creates full path breadcrumbs
  - Handles foreign key constraints properly

#### Unified Loaders (root directory)
- **load_unified_icd10cm.py**: Advanced ICD-10-CM loader with vector embeddings
  - Loads into unified ontology.icd schema
  - Generates OpenAI embeddings (currently mock for testing)
  - Supports both pgvector and JSON fallback
  - Comprehensive metadata tracking
  - Batch processing with parent relationship resolution

- **load_unified_icd11.py**: ICD-11 TSV loader with vector embeddings
  - Processes ICD-11 TSV format with Foundation/Linearization URIs
  - Handles complex hierarchy parsing with dash counting
  - Supports class kinds (chapter, block, category)
  - Residual code detection
  - Full path construction with cycle detection

### 3. Database Schema Architecture

#### Legacy Schema (setup_knowledgegraph.sql)
- Simple ontology.icd table with basic hierarchy support
- Foreign key self-reference for parent_code
- Basic indexing on parent_code, version, full_path

#### Unified Schema (unified_icd_schema.sql)
- Advanced ontology.icd table supporting both ICD-10-CM and ICD-11
- pgvector extension with vector(1536) for OpenAI embeddings
- JSON fallback (term_vector_json) when pgvector unavailable
- Cross-reference table for ontology mapping
- Comprehensive indexing including vector similarity search
- Metadata JSONB field for extensible data storage
