## 3. What Was Proved

### The Graph Grows Under Query Pressure

Every step of the detective run mutated the graph. No step left it unchanged. The mutations were not corrections to errors — they were new synthetic events generated by the EoH reasoning modules based on what the evidence implied. The graph at E1 is objectively richer than the graph at A1.

This is the core PortalVision invariant: **the graph grows with attention.** This run is the first time it was observed across a full multi-step reasoning chain, not just in isolation.

### The Router Selected Correctly

The LLM router, given each question, correctly identified the relevant EoH modules (M1, M2, M3A, M12, M13 for terrain; M50, M48C for diagnostic landscape; etc.) and correctly bypassed irrelevant clinical guidelines. For the A1 terrain question, the router selected only `eoh_2025` and `ethos_model` — ignoring all 74 disease-specific guidelines. This is correct: terrain mapping is not a guideline lookup. The routing signal is clean.

### The System Is Honest About What It Doesn't Know

Three of six steps explicitly flagged diagnostic uncertainty. The "other" category (44% of diagnostic signal) was not hidden or smoothed over — it was surfaced, named, and flagged for resolution. Step E1 (meta_calibration) correctly identified imaging gaps, symptom ambiguity, and treatment response uncertainty as the specific limiters.

> *"The patient's timeline data is extensive... but contains gaps and inconsistencies, especially in imaging and symptom data, which limit definitive diagnostic conclusions."*

That is honest state representation. Most systems hide this. This one reports it.

### 76 Clinical Guidelines Were Available. The System Used 2.

The router narrowed from 76 loaded guidelines to `eoh_2025` + `ethos_model` for the terrain and diagnostic steps. This is exactly correct — Norman Roberts' case does not fit neatly into any single-disease guideline. The multi-system framing (MG + ILD + AFib + spinal stenosis + reactive airway disease) requires the EoH integrative framework, not the ACR RA 2021 rubric. The router got this right without being told.

## 4. What Remains Weak

### The "Other" Category (44%)

This is the system's most important signal and its most important gap simultaneously. "Other" means the diagnostic clustering algorithms could not assign these events to a named disease signature. This is not wrong — it is honest. Norman Roberts genuinely has conditions that don't map cleanly onto standard autoimmune phenotypes.

But "other" at 44% is also an ontology coverage gap. Sub-clustering "other" into phenotype signatures (fibrotic, neuromuscular, autonomic) would both improve reasoning quality and reduce the entropy bucket. This is the v1.1 task.

### Timestamp Fallback (DOB Anchoring)

Many events in this run were anchored to `1947-08-17` (patient DOB) — the pre-repair fallback for unparseable timestamps. The 99.6% timestamp repair was done after this graph was built. The next run should be executed against the repaired graph. The expectation: the temporal reasoning in steps A1 and D1 will substantially improve because 2,553 events that were previously floating in time will be correctly positioned.

### No Causal Depth Measurement

The system identified that prednisone taper correlated with symptom worsening. It did not rigorously quantify the lag, the magnitude, or the confounders. "Causal attribution" requires drug_response edges with direction and confidence, which are on the roadmap (T2.3) but not yet built. What the system produced is correct temporal co-occurrence, not causal inference.

### Answer Delta Still Unmeasured

The graph mutated +12 events / +19 edges across this run. The next run against the same query will have a richer graph to traverse. **The delta has not been shown.** Until we run the same query twice — once against the pre-mutation graph and once against the post-mutation graph — and compare the answers, "mutation improves reasoning" is demonstrated mechanism, not demonstrated outcome.

This remains the one open condition for a clean v1.0 receipt.
